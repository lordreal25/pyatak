# ПЯТАК

Мобильный маркетплейс аренды спецтехники для Казахстана на Expo, React Native и TypeScript.

## Запуск

```powershell
npm install
npm run start
```

Для проверки типов:

```powershell
npm run typecheck
```

## Возможности MVP

- Главный экран, поиск по каталогу, категории, фильтры, избранное и карточки техники.
- Подробная страница техники и отправка заявки с датой, длительностью и адресом объекта.
- Заказы с серверными статусами: клиент отправляет заявку или отменяет ожидающую, владелец подтверждает, отклоняет и обновляет ход работ.
- Профиль с авторизацией по SMS, синхронизацией имени и городских/языковых настроек, серверными уведомлениями и избранным.
- Демонстрационный чат, русская и казахская локализация.
- Кабинет владельца с показателями и пошаговым созданием объявления, включая выбор фотографий.
- Без Supabase приложение работает с демонстрационными данными и локальным хранилищем. При настроенном Supabase аккаунт, заказы, избранное, профиль и настройки синхронизируются с сервером.
- Анимированная нижняя навигация, ценовой слайдер и переключатели адаптированы к приложению по мотивам [Animated Bottom Navigation](https://nativecn-ui.vercel.app/components/bottom-navigation), [Range Slider](https://nativecn-ui.vercel.app/components/range-slider) и [Switch Toggle](https://nativecn-ui.vercel.app/components/switch-toggle) из NativeCN UI. Реализация использует React Native API и не добавляет UI-зависимостей.
- Для мобильного интерфейса подключены NativeWind и React Native Reusables — библиотека компонентов в стиле shadcn/ui для React Native. Добавлены базовые компоненты Button и Text в `components/ui`, тема Пятака и конфигурация NativeWind для iOS, Android и web.

Добавить другие мобильные компоненты можно командой:

```powershell
npx @react-native-reusables/cli@latest add input
```

Для новых компонентов используйте классы NativeWind (`className`) и добавляйте их в каталог `components/ui`.

## Подключение Supabase

1. Создайте Supabase-проект и добавьте `EXPO_PUBLIC_SUPABASE_URL` и `EXPO_PUBLIC_SUPABASE_ANON_KEY` из `.env.example` в локальный `.env`. Используйте только публичный ключ клиента — никогда не добавляйте `service_role` или secret key в Expo-приложение.
2. Примените миграции по порядку из `supabase/migrations`: сначала `20261029000000_initial_schema.sql`, затем `20261029010000_account_preferences_and_order_cancellation.sql`. Их можно выполнить через Supabase SQL Editor или Supabase CLI.
3. В Supabase Auth включите Email provider для регистрации и входа по почте с паролем. Если включено подтверждение email, пользователь должен перейти по ссылке из письма перед входом. Вход по SMS доступен дополнительно: для него включите Phone Auth и настройте SMS-провайдера.
4. Перезапустите Expo после добавления переменных окружения: `npm run start -- --clear`.

После входа по email/паролю или SMS профиль, язык и город, избранное и заказы загружаются из Supabase. Заказ является заявкой, а не платежом; онлайн-оплата не подключена. Миграции подготовлены в проекте, но применить их и проверить реальные запросы можно только после настройки Supabase-проекта и его ключей.

Каталог в демонстрационном режиме использует локальные примеры. Карта, push-уведомления и платежи не подключены.
